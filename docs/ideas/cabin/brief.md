# 선실 지도 아이디어 브리프 (2026-10-29)

Starship의 **선실**(`/crew/[id]`)은 프로젝트 하나의 전체 그림인 **지도**(`map.json`, 형식 `starship-map/1`)를 보여 준다. 설계는 [`docs/map.md`](../../map.md), 스키마는 [`src/protocol/map.ts`](../../../src/protocol/map.ts).

지금 화면(1단계)은 squarified treemap이다. 맨 위 구역이 대륙, 그 안 구역이 땅이고, 넓이 = `size`, 상태는 색과 무늬(안개 점무늬, 공사 노란 줄무늬, 완공 초록과 깃발, 막힘 붉은 테두리), 표지는 아이콘(⑂ 📡 ⚠), `here` 구역에 승무원 동물이 앉는다. 오른쪽 판에 고른 구역의 요약·다음·표지·링크, 위쪽 줄에 진행률·처음 → 지금(+발견)·지도 갱신 시각.

## 사용자 피드백 (원문 요지)

> 지금도 좋지만, 옛날 윈도우 조각모음 결과를 보는 것 같다. 직관적이지만 어색한 부분이 있다. 무언가를 만든다거나, 그런 개념들을 들여서 좀 더 직관적이고 재미있는 공간을 만들 수 있을까?

설계 문서의 출발점은 "닌텐도가 맵 곳곳에 '공사중' 표지를 붙여 두고 사람들이 맵을 돌아다니며 만들었다"는 이야기다. **프로젝트 하나를 내가 만들어 가는 세계 한 장으로** 보이게 하는 것이 목표다.

## 데이터 (바꾸지 않는다. 필요하면 선택 필드를 더하는 정도)

- 지도: `title`, `goal`(끝났다고 볼 기준), `baselineAt`(처음 계획 날), `updatedAt`, `here`(지금 공사하는 구역 id), `regions[]`
- 구역: `id`, `title`(한국어, 짧게는 2자, 길게는 25자 이상도 있다), `parent`(최대 3단), `status`(fog 안개 · building 공사중 · done 완공 · blocked 막힘 · dropped 버림), `size` 1~5, `summary`, `next`, `since`, `found`(처음 계획에 없다가 생긴 날), `links[]`, `signs[]`
- 표지: `fork` 갈림길(정할 사람 `owner`, `me`면 내가. 선택지·추천·open/decided) · `talk` 교신(상대 `with`, draft/sent/waiting/done) · `risk` 위험
- 진행률 = 완공 size 합 ÷ 버림 뺀 전체 size 합. 자식 있는 구역은 자식으로만 센다.
- 승무원(프로젝트)마다 동물 선원이 있다(고양이·여우·토끼·너구리 등, `src/ui/crew/Animal.tsx`의 SVG). 상태: working · needs-you · idle · off.
- 실제 지도 규모: 데모는 20구역, 실제 프로젝트 지도는 31~41구역이고 그중 절반 이상이 최근 일주일 안에 생긴 "발견" 구역이다. 항목은 계속 늘어난다.

## 지켜야 할 것 (교훈)

- **3초 안에 읽혀야 한다**: 얼마나 됐나(진행률), 지금 어디를 짓나(`here`), 내가 정할 것(owner=me인 열린 갈림길), 막힌 곳. 그림은 크기·위치·불빛·캐릭터의 손짓처럼 해석 없이 읽히는 것만 정보를 맡는다. 은유 그림만으로 정보를 맡기면 해석이 필요해 애매했다(조종석 1·2차 시안에서 얻은 교훈).
- **좌표를 손으로 적지 않는다**: 구역이 늘어도 화면이 자동으로 배치해야 한다. 구역을 하나 더하면 기존 모습이 크게 흔들리지 않아야 좋다.
- 40구역, 긴 이름, 3단 계층에서 무너지지 않는다. 구역이 3개뿐이어도 어색하지 않다.
- 조종석·선실이 있는 **우주선** 세계와 어울린다. 동물 선원이 산다.
- 공개 저장소다: 영화·드라마·게임 속 캐릭터와 특정 기존 게임의 재현(이름만 바꾼 것 포함)은 쓰지 않는다. 장르의 관습(건설, 탐험, 정원 가꾸기 같은)은 좋다. 외부 자산은 라이선스가 분명하고 적을수록 좋다.
- 화면은 파일을 쓰지 않는다. 고칠 일은 갈림길 답하기 같은 동작으로 비서에게 넘긴다(`docs/map.md` "요구사항이 바뀌면").

## 조건

- Next.js + React, SVG·Canvas 2D·WebGL(three.js/react-three-fiber) 모두 쓸 수 있다. 시안 하나를 하루~이틀 안에 만들 수 있어야 한다.

## 출력

지정받은 파일에 JSON 배열 25개. 항목마다:

```json
{
  "id": "A01",
  "title": "짧은 이름",
  "pitch": "한두 문장 컨셉",
  "scene": "선실에 들어서면 보이는 것: 화면 구성과 분위기",
  "regions": "구역과 계층이 무엇으로 그려지나, 어떤 규칙으로 자동 배치하나(size는 어떻게 드러나나)",
  "status": "다섯 상태(안개·공사중·완공·막힘·버림)가 어떻게 보이나",
  "signs": "갈림길·교신·위험, 특히 내가 정할 갈림길이 어떻게 눈에 띄나",
  "here": "지금 여기와 동물 선원이 무엇을 하고 있나",
  "growth": "진행률, 처음 계획 대비 늘어난 구역(발견), 시간에 따른 변화가 어떻게 보이나",
  "interact": "누르면 무엇이 열리나, 갈림길에 답하러 가기·링크",
  "scale": "40구역·긴 이름·3단·구역 3개일 때",
  "tech": "구현 방법과 필요한 외부 자료",
  "why": "이 안이 특별한 이유 한 문장"
}
```

모든 글은 일상 한국어로, 항목당 600자 안팎. 25개가 서로 다른 구조여야 한다(이름만 다른 변형 금지).
