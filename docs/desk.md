# 선실의 책상 (`starship-desk/1`) — 설계

선실(`/crew/{id}`)에 지도와 함께 책상 한 장을 놓는다. 그 세션이 **나를 기다리는 것**과 **지금 하는 일**을 적는다. 형식의 원본은 [`src/protocol/desk.ts`](../src/protocol/desk.ts)이고, 끝점은 [`protocol.md`](protocol.md)의 `GET {base}/v1/crew/{id}/desk`다.

## 왜

세션이 여럿이면 세션마다 창을 찾아가서 "데모에서 뭘 봐야 해?", "지금 무슨 상태야?"를 다시 물어야 한다. 그런데 세션이 기다리는 것은 대개 정해진 모양 몇 가지다.

- 둘 중 하나 고르기(데모 주소 각각, 추천 있음)
- 만든 것 확인하기(주소와 보실 점)
- 바깥 일 승인하기(push·배포)
- 글로 답하기

세션이 이것을 책상에 적어 두면, 나는 선실에서 묻지 않고 보고 그 자리에서 답한다. 비서가 그 답을 세션 창에 넣는다.

## 모양

```jsonc
{
  "desk": "starship-desk/1",
  "updatedAt": "2026-10-31T10:12:00+09:00",   // 필수. 책상을 마지막으로 고친 때
  "waiting": [
    {
      "id": "coupon-entry",                   // 필수. 책상 안에서 겹치지 않게
      "type": "decide",                       // decide · check · approve · answer
      "title": "쿠폰 입력 방식 두 가지 중 고르기", // 필수. 내가 할 일 한 줄
      "detail": "둘 다 데모로 띄워 뒀어요",      // 선택. 왜·맥락 짧게
      "since": "2026-10-31T09:30:00+09:00",   // 선택. 언제부터 기다렸나
      "blocks": true,                         // 선택. 세션이 이것 때문에 멈췄나
      "options": [                            // decide는 2개 이상 필수
        { "id": "inline", "label": "결제 칸 안에 바로 입력", "url": "https://...", "note": "한 화면에서 끝나요", "recommended": true },
        { "id": "sheet", "label": "쿠폰함을 아래에서 열기", "url": "https://...", "path": "/Users/me/Desktop/sheet.png" }
      ],
      "items": [                              // check는 1개 이상 필수
        { "label": "결제 완료 색종이", "url": "https://...", "look": "2초 안에 끝나나" },
        { "label": "결제 완료 화면 녹화", "path": "/Users/me/Desktop/confetti.mov", "look": "2초 안에 끝나나" }
      ],
      "after": "고른 방식만 남기고 시험을 다시 돌려요" // 선택. 답하거나 승인하면 세션이 할 일
    }
  ],
  "doing": [
    { "id": "unit", "title": "쿠폰 계산 단위 시험 돌리는 중", "since": "2026-10-31T10:09:00+09:00" }
  ]
}
```

| 종류 | 뜻 | 꼭 있어야 하는 것 | 카드에 보이는 것 |
|---|---|---|---|
| `decide` | 고르기 | `options` 2개 이상 | 선택지마다 이름·설명·데모 주소·파일 보기/열기·추천 표시, 고르기 버튼 |
| `check` | 확인하기 | `items` 1개 이상 | 항목마다 주소·파일 보기/열기와 보실 점, "확인함"·"고칠 것 있음" 버튼과 글 |
| `approve` | 승인하기 | — | "승인"·"보류" 버튼 |
| `answer` | 글로 답하기 | — | 글 칸 |

`options[]`와 `items[]`의 `path`(선택)는 이 맥의 파일 절대 경로다(2026-11-01 더함, 형식 이름은 그대로). 스크린샷·PDF·녹화처럼 주소가 없는 결과물을 경로 복사 없이 본다. 카드는 `path`가 있으면 "보기"(새 탭에서 `/api/files?path=…`)와 "열기"(맥의 맞는 프로그램) 단추를 보인다. 허용 폴더 밖이거나 숨김·실행 파일이면 서버가 거절한다. 자세한 규칙은 [`files.md`](files.md).

`after`는 처음에 `then`이었다. `then`이 있는 객체는 `await`나 동적 `import`에서 Promise로 오해받는다. biome도 `noThenProperty`로 막는다. 그래서 `after`로 바꿨다.

## 꼭 지킬 규칙과 보장 방법

| 규칙 | 보장 |
|---|---|
| `waiting[].id`가 겹치지 않는다 | `checkDesk`가 잡는다. Task id가 여기서 나오므로, 겹치면 답이 엉뚱한 곳으로 간다 |
| decide는 선택지 2개 이상, check는 항목 1개 이상 | `Waiting` 스키마(`superRefine`) |
| 한 기다림 안에서 `options[].id`가 겹치지 않는다 | `checkDesk` |
| 날짜는 `Date.parse`로 읽힌다 | `When` 스키마 |
| 주소는 http(s)만 | `WebUrl` 스키마. 카드가 주소를 그대로 링크로 여니까 `javascript:`·`file:` 같은 주소는 막는다 |
| `path`는 `/`로 시작하는 절대 경로만 | `FilePath` 스키마. 허용 폴더·숨김·확장자는 Starship 서버가 보기·열기 때 다시 본다([`files.md`](files.md)) |
| 모르는 필드는 버린다 | zod 기본 동작. 같은 버전 안에서 필드를 더할 수 있다 |

비서와 Starship은 같은 `parseDesk`로 검사한다. 서버 모드에서는 Starship이 받은 책상을 다시 검사한다. 걸리면 `desk: null`로 바꾸고 문제를 화면 위쪽에 알린다.

## 답하기

책상은 읽기 전용이다. 답은 이미 있는 Task 동작(`POST /v1/actions`의 `answer`)으로 보낸다.

1. 비서는 기다림 하나하나를 Task로도 내보낸다. id는 `desk:<crewId>:<waitId>`(`deskTaskId`)다. 동작은 `answer`와 `snooze`이고, 세션 창이 있으면 `focus`도 붙는다. `dismiss`는 없다. 책상은 세션이 지우는 것이라, 선실에서 치워도 다음에 읽을 때 다시 생기기 때문이다.
2. 고를 것(`choices`)은 `deskChoices`가 정한다. decide는 선택지 `label`들, approve는 `["승인","보류"]`, check는 `["확인함","고칠 것 있음"]`이다. answer는 고를 것 없이 글만 받는다.
3. 선실 카드는 그 Task id로 `answer`를 보낸다.
   - 고른 것에 글을 덧붙이면 `"<고른 것> — <글>"`처럼 한 줄로 잇는다(`deskAnswer`).
   - 글만 쓰면 글을 그대로 보낸다.
   - 줄바꿈은 공백으로 바꾼다. 세션 창에서는 줄바꿈이 곧 보내기라서다.
4. 서버는 답을 받으면 그 기다림을 할 일에서 뺀다. 세션이 책상 파일을 다시 쓰기 전까지 책상에서도 가린다.

Task를 따로 두는 이유는 책상을 모르는 화면 때문이다. 조종석과 알림도 같은 기다림을 할 일로 보여 주고 답할 수 있다. 책상은 그 할 일에 맥락(데모 주소, 보실 점, 답한 뒤 할 일)을 더한 그림이다.

스냅샷에 책상 Task가 아직 없을 수 있다(서버가 아직 내보내지 않았거나, 미뤄 두었을 때). 그러면 카드는 답 버튼 대신 "아직 답할 수 없어요"를 보인다.

## 화면

- **선실 오른쪽 판**: 맨 위에 "책상"과 "지도" 두 칸이 있다. 기다리는 것이 있으면 책상이 먼저 열린다. 지도에서 구역을 누르면 지도 칸으로 옮긴다.
- **기다림 카드**: 종류마다 머리 색과 이름이 다르다(고르기·확인·승인·답하기). `blocks`면 "세션 멈춤" 표가 붙는다. 맨 아래 한 줄은 `after`("답하면: …")다.
- **하는 일**: 카드 아래에 한 줄씩, 얼마나 됐는지와 함께 보인다.
- **지도가 없는 승무원**: 가운데에 "지도가 아직 없어요"를 두고, 오른쪽 판에는 책상만 보인다.
- **조종석**: 승무원 표시 옆에 기다림 수(`Crew.desk.waiting`)가 작게 보인다.

## 요구사항이 바뀌면

- 새 종류(예: 순서 정하기)를 더하려면 `WaitType`, `deskChoices`, 카드 하나를 더한다. 옛 화면은 모르는 종류를 받으면 형식 검사에서 걸린다. 그래서 종류를 더할 때는 Starship을 먼저 올리고, 그 뒤에 비서가 새 종류를 쓴다.
- 필드를 더하는 것은 같은 버전 안에서 된다. 이름이나 뜻을 바꾸면 `starship-desk/2`로 올린다.

## 다른 방법과 고른 이유

- **map.json 표지(sign)로 적기**: 지도는 프로젝트 전체를 오래 담는 그림이고, 저장소에 커밋된다. 기다림은 몇 분에서 몇 시간짜리라 커밋할 것이 아니다. 그래서 따로 둔다. 비서 쪽 파일은 `~/.local/state/secretary/desk/<crewId>.json`이다.
- **Task에 필드를 더하기**: Task는 모든 출처(채팅·이슈 등)가 같이 쓰는 모양이다. 데모 주소나 보실 점 같은 세션 전용 필드를 넣으면 무거워진다. 그래서 책상을 따로 두고 Task와는 id로만 잇는다.
