# 보안 구역 — AI 세션의 1Password 사용 기록

1Password 팝업이 떴을 때 `/secure`를 열어 맨 위의 신청서만 보고 승인할지 정한다. 신청서는 AI 세션이 1Password CLI(`op`)를 부르기 전에 쓰는 글로, 누가·언제·무슨 목적으로·어떤 순서로·무엇을 꺼내는지 적는다. 신청서가 없으면 비서의 hook이 AI의 호출을 막는다. 사람이 터미널에서 직접 부른 것은 막지 않고, 터미널·폴더 같은 맥락과 함께 기록만 남는다.

들어가는 길은 조종석 오른쪽 연료 계기 아래 "보안 구역" 줄이다. 휴대폰에서도 같은 주소로 본다.

코드: [`src/protocol/secure.ts`](../src/protocol/secure.ts)(형식), [`src/server/secure.ts`](../src/server/secure.ts)·[`src/app/api/v1/secure/route.ts`](../src/app/api/v1/secure/route.ts)(중계와 값 지우기)·[`src/app/api/v1/secure/ack/route.ts`](../src/app/api/v1/secure/ack/route.ts)(확인함 표시), [`src/secure/`](../src/secure/)(판정·가림·묶기 순수 함수), [`src/ui/secure/`](../src/ui/secure/)(화면), [`src/demo/secure.ts`](../src/demo/secure.ts)(데모 기록).

## 화면

- **맨 위**: 지금 유효한 신청서 수와, 가장 최근 신청서를 크게 보인다. 세션 이름, 목적, 할 일 목록, 꺼낼 것(참조와 동작), 카드, 남은 시간. 나머지 유효한 신청서는 작은 카드로 그 아래에 둔다. 유효한 신청서가 하나도 없으면 "직접 부른 것이 아니라면 팝업을 승인하지 마세요"라고 알린다.
- **기록**: 호출과 신청서를 탭으로 나눠 본다. 기간(1시간·오늘·7일·전체), 누가(모두·AI·직접 실행), 세션으로 거른다. 신청서는 AI만 쓰므로 직접 실행으로 거르면 비어 있다.
- **hook·wrapper 묶기**: AI 호출 하나에 hook 기록(Claude Code가 명령 전에 남김)과 wrapper 기록(`op`를 감싼 스크립트가 남김)이 둘 다 생길 수 있다. 같은 세션 열쇠, 같은 하위 명령, 시각 차이 5초 안이면 한 줄로 묶는다. 한 줄에는 hook 하나와 wrapper 하나까지만 넣어서, 같은 명령을 잇달아 부르면 두 줄이 된다. 사람의 직접 실행은 묶지 않는다.
- **신청서 연결**: 신청서 id가 붙은 호출은 그 신청서의 세션과 목적을 함께 적는다. 신청서마다 이어진 호출 수를 센다.
- **직접 실행**: 사람이 부른 호출은 "직접 실행"으로 표시하고 터미널 프로그램, tty, 폴더(git 저장소 뿌리), 부모 명령을 보인다.
- 5초마다 다시 읽는다. 읽기에 실패하면 마지막으로 받은 기록을 계속 보이고 실패 이유를 아래에 적는다.

## 빨간 표시

다음 중 하나면 그 줄을 빨갛게 하고 까닭을 한 줄로 적는다. 묶은 줄은 기록 하나라도 해당하면 빨갛다.

- `decision`이 `denied`: "hook이 막은 호출이에요"
- AI의 wrapper 기록인데 `requestId`가 없음: "신청서 없이 나간 호출이에요". wrapper 기록은 `op`가 실제로 실행될 때 남으니, 신청서 없이 실행까지 갔다는 뜻이다. hook 기록에 신청서가 없는 것만으로는 빨갛게 하지 않는다. 그때는 hook이 막았는지(`denied`)로 판단한다.
- 값을 건드리지 않는 호출은 신청서가 없어도 빨갛게 하지 않는다(`isHarmlessCall`). `op --version`처럼 판본이나 도움말만 본 호출이다. 하위 명령(`command.sub`)이 빈 글이고, 인자가 하나 이상이며 모두 `--version`·`-v`·`--help`·`-h`·`help` 중 하나일 때만 그렇게 본다. 인자가 없거나 다른 인자가 하나라도 섞이면 빨갛게 둔다. 놓치는 것보다 한 줄 더 빨간 편이 낫기 때문이다. `denied`는 이 경우에도 늘 빨갛다.

맨 위 신청서 제목 옆에 "확인 안 한 빨간 줄 N건"을 보인다. 기간·거르기와 상관없이 받은 기록 전체로 센다. 0건이면 빨간 강조 없이 흐린 글로 둔다.

## 확인함

빨간 줄이 쌓이면 새 빨간 줄이 묻힌다. 그래서 사용자가 살펴본 빨간 줄은 "확인함"으로 표시한다. 표시해도 **기록은 지우지 않는다**. 줄은 빨간 강조를 거두고 흐리게 남으며, 빨간 까닭과 "✓ 확인함 · 시각", "되돌리기" 단추를 보인다.

- 누르면 그 줄에 묶인 모든 기록 id(hook·wrapper)를 보낸다. 줄은 빨간 까닭이 있는 기록이 모두 확인됐을 때만 확인함으로 보이고, 시각은 그중 가장 늦은 것이다(`rowAck`). 그래서 묶인 기록 하나만 확인된 줄은 여전히 빨갛다.
- 키보드로도 누를 수 있다. 실패하면 줄 아래에 짧게 이유를 적는다.
- **저장 위치는 비서**다. 맥과 휴대폰이 같은 비서 기록을 읽으니 어디서 눌러도 같은 상태가 보인다. Starship은 표시를 따로 저장하지 않는다.
- 데모 모드는 Starship 서버 메모리에 두고 데모 기록에 입힌다. 화면 확인용이라 서버를 다시 띄우면 사라진다. 서버 연결 모드에서는 이 메모리를 쓰지 않는다.

Starship 끝점: `POST /api/v1/secure/ack`, 본문 `{ "ids": string[], "undo"?: true }`. id는 1~50개. 같은 출처 요청만 받고(아니면 403), 본문은 64KB까지(넘으면 413), 형식이 틀리면 400. 성공하면 `{ source, acked, undone, unknown }`, 비서가 실패하면 502와 이유.

비서 끝점(Starship이 부른다):

- `GET {origin}/api/secure`의 `calls[]` 항목에 선택 칸 `ack: { "at": ISO 또는 밀리초, "by"?: string }`. 없거나 `null`이면 확인 안 함.
- `POST {origin}/api/secure/ack`, 본문 `{ "ids": string[], "undo"?: true, "by": "starship" }` → 200 `{ "acked"?: string[], "undone"?: string[], "unknown"?: string[] }`. 같은 id를 다시 표시해도 처음 시각이 남는다(멱등). 비서는 `Origin`이 자기 origin이 아니거나 `content-type: application/json`이 없으면 403으로 막으니, Starship은 두 헤더를 싣는다. 시간 제한은 10초.
- 비서가 이 끝점을 모르면(404) "비서가 아직 확인 표시를 받지 못해요"를 502로 돌려준다. 이때 기록 보기는 그대로 된다.
- 표시한 뒤에는 함께 쓰던 보안 기록(1.5초)을 버려 다음 읽기가 새 상태를 받는다.

## 값 보호

호출 인자, 신청서의 목적·할 일·참조, 부모 명령에서 비밀값처럼 보이는 낱말은 화면에 그리지 않는다. DOM에도 넣지 않고, 눌러도 보이지 않는다. 대신 "값처럼 보이는 글자를 숨겼어요"라고 적는다.

- 판정(`looksSecret`): 20자 이상, 빈칸·`op:` 없음, 점·밑줄·붙임표·슬래시로 나눈 가장 긴 덩어리가 16자 이상이고 소문자·대문자·숫자 중 두 가지 이상이 섞이며 글자당 엔트로피가 3.3비트 이상. `이름=값` 꼴이면 등호 뒤만 본다. 덩어리를 보는 까닭은 `blog.deploy.production.v2`처럼 글자 종류가 섞였어도 짧은 낱말을 이은 이름을 숨기지 않기 위해서다. 슬래시가 들었다고 건너뛰지 않는 까닭은 base64 값에 `/`와 `+`가 섞이기 때문이다. 경로는 덩어리가 짧은 낱말이라 걸리지 않는다. 1Password 항목 id(26자 영숫자)는 값이 아니지만 숨겨질 수 있다. 새는 것보다 덜 위험해서 그대로 둔다.
- Starship 서버(`/api/v1/secure`)가 먼저 같은 판정으로 그 글자를 `<값 숨김>`으로 바꿔 보낸다. 그래서 휴대폰으로 가는 응답에도 남지 않는다. 화면도 받은 인자를 한 번 더 판정한다.
- 비서가 미리 가려 보낸 `<가림>`은 그대로 보인다.

## 이름 가림

금고·항목 이름은 처음엔 일부만 보이고, 누르면 전체가 보이고, 다시 누르면 다시 가린다. 맥과 휴대폰에서 같고, 키보드로도 누를 수 있다. 화면 표시용이라 응답에는 전체 이름이 들어 있다는 점이 값 보호와 다르다.

- 대상: `op://` 참조(신청서의 `items[].ref`, 인자 속 참조), `--vault`·`--account`·`--fields`·`--field`·`--tags` 값, `op item`·`op document` 뒤 동사 다음의 항목 이름.
- 규칙(`maskSegment`): 슬래시로 나눈 조각마다 가린다. 3자 이하는 앞 1자, 5자 이하는 앞 2자, 10자 이하는 앞 3자만 남긴다. 그보다 길면 앞 35%와 끝 2~3자를 남긴다. 예: `op://Personal/blog.deploy.prod/DEPLOY_TOKEN` → `op://Per•••/blog.d•••rod/DEPLO•••EN`. `?attribute=otp` 같은 물음표 뒤와 `label=` 같은 등호 앞은 그대로 둔다.

## 데이터 출처

형식의 원본은 비서 서버의 `GET /api/secure?limit=200`이다. 비서가 이 끝점을 만들고, Starship은 [`src/protocol/secure.ts`](../src/protocol/secure.ts)로 읽는다.

- 주소: `STARSHIP_SERVER_URL`의 origin에 `/api/secure`를 붙인다. 비서는 Starship 프로토콜 끝점을 `/starship/v1/…` 아래에, 자기 API를 서버 뿌리의 `/api/…` 아래에 두기 때문이다.
- 응답 `{ requests: [...], calls: [...] }`, 둘 다 최근순. 시각(`at`, `expiresAt`)은 ISO 글이나 밀리초 숫자.
- 바깥(두 배열)이 틀리면 502. 항목 하나가 틀리면 그것만 빼고 `problems`에 적는다. 화면 아래 "형식이 틀려 뺀 기록"에서 볼 수 있다.
- 비서가 404면 `status: "none"`으로 주고, 화면은 "본부에 보안 기록이 아직 없어요"를 보인다. 실패나 4초 시간 초과는 502와 이유.
- **서버 연결 모드에서는 데모 기록을 절대 섞지 않는다.** 진짜 보안 기록으로 오해하면 안 되기 때문이다. 데모 기록은 `STARSHIP_SERVER_URL`이 없을 때만 내고, 화면 머리에 "데모 · 지어낸 기록이에요"를 붙인다. 데모의 금고·항목·세션 이름은 모두 지어낸 것이다.
