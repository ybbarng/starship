# 그리는 박자 — 하루 종일 켜 둬도 가볍게

선실은 앱으로 설치해 하루 종일 켜 두는 화면이다. 3D 별 하늘과 CSS 애니메이션 140개 남짓(승무원 캐릭터, 실내 깜빡이, 연료실 불꽃)이 쉬지 않고 1초에 60번 바뀌어서, 창 하나가 CPU 코어 1.5개쯤(Chrome GPU·탭·WindowServer 합계)을 계속 썼다(2026-11-02 비서 측정). 그래서 앱 전체가 한 박자에 맞춰 바뀌게 했다.

코드: [`src/ui/kit/pace.ts`](../src/ui/kit/pace.ts)(규칙·순수 함수), [`src/ui/kit/PaceRoot.tsx`](../src/ui/kit/PaceRoot.tsx)(박자기, `providers.tsx`에 하나), [`src/sky/SpaceView.tsx`](../src/sky/SpaceView.tsx)의 `FramePacer`·`CameraRig`. 시험: [`src/ui/kit/pace.test.ts`](../src/ui/kit/pace.test.ts).

## 규칙

| 상태 | 1초에 바뀌는 횟수 |
|---|---|
| 움직이는 중: 비행·끌기·놓은 뒤 미끄러짐·자리 잡기, 누르기·휠·키 입력 뒤 1.5초 | 화면 새로 고침마다(보통 60) |
| 앱 창을 보는 중(초점 있음), 가만히 | `IDLE_FPS` = 15 |
| 창은 보이지만 다른 앱에서 일하는 중(초점 없음) | `BLUR_FPS` = 6 |
| 창이 안 보임(가려짐·최소화·다른 데스크톱, `document.hidden`) | 0 |

움직임은 모두 시간(`Date.now`, 애니메이션 시각)으로 정해진다. 덜 자주 바꿔도 자리와 속도는 그대로이고 부드러움만 준다. 저절로 도는 하늘은 1초에 화면 12px쯤 움직이므로 15번이면 한 번에 1px 남짓이다.

## 어떻게 맞추나

- **3D 하늘**: Canvas를 `frameloop="demand"`로 두고, `FramePacer`가 박자마다 `invalidate()`한다. `CameraRig`는 비행·끌기·미끄러짐·자리 잡기 중에 `markBusy`를 불러 매 프레임으로 올린다. 저절로 도는 것만 남으면 쉰다(그때 카메라는 목적 자리에서 기본 거리의 0.4%쯤 뒤처지므로 1%를 경계로 둔다).
- **워프 줄기(2D 캔버스)**: 워프 중에만 매 프레임 그린다. 아닐 때는 한 번만 지우고 1초에 10번 워프인지만 살핀다.
- **CSS 애니메이션**: `stepAnimations`가 처음 본 돌던 애니메이션을 멈추고(`pause`), 박자마다 시각(`currentTime`)만 옮긴다. 앱이 스스로 멈춰 둔 것·끝난 것은 건드리지 않고, 끝이 있는 것은 끝에 닿으면 끝낸다. 읽기는 처음 볼 때 한 번만, 쓰기보다 먼저 한다(쓰고 나서 읽으면 그때마다 스타일 계산이 강제된다). CSS 전환(transition)은 짧고 손으로 일으키는 것이라 그대로 둔다.
- **새로 시작한 애니메이션**: 캐릭터의 짧은 동작(`ActClock`)은 몇 초마다 새 애니메이션을 만든다. 다음 박자를 기다리면 그사이 매 프레임 돌고, 캐릭터가 여럿이라 거의 끊이지 않는다. 그래서 `animationstart`를 받아 그 요소의 애니메이션만 바로 박자에 넣는다.
- **SMIL**(SVG `<animate>`, 연료실 불꽃의 일렁임): 바깥 svg를 `pauseAnimations()`로 멈추고 박자마다 `setCurrentTime()`.

## 측정(헤드리스 Chrome, 1372×872, 픽셀 밀도 2, 데모 자료)

WindowServer 몫은 빠진 숫자다. 실제 앱 창에서는 비서가 잰다.

| 화면 | 전 | 후: 초점 있음 | 후: 초점 없음 |
|---|---|---|---|
| 홈(조종석) | 0.70코어(GPU 0.36, 탭 0.34) | 0.20~0.26 | 0.16~0.20 |
| 연료실 | 0.26 | 0.17 | 0.06 |

같은 자리에서 여러 번 재면 ±0.04쯤 흔들린다. 홈에 남은 몫은 하늘과 CSS가 대략 반씩이고, 5초마다 새로 받는 상태와 이름표 자리 계산이 조금 더한다.

## 바꿀 때

- 더 가볍게: `BLUR_FPS`를 낮춘다(4면 더 끊겨 보인다). 하늘 픽셀 밀도(`dpr={[1, 2]}`)는 헤드리스 측정에서 차이가 작아 그대로 두었다.
- 새 애니메이션: CSS·SMIL로 만들면 저절로 박자를 따른다. `requestAnimationFrame`으로 직접 돌리는 것은 박자를 따르지 않는다. 계속 도는 것이면 `onPaceTick`에 건다. 손으로 일으켜 잠깐 도는 것은 그대로 둬도 된다.
- 앱 CSS가 `animation-play-state`로 애니메이션을 멈췄다 다시 트는 일이 생기면: 박자기가 이미 멈춰 둔 것은 다시 틀어도 박자기 시각을 따른다. 그런 곳이 생기면 `stepAnimations`가 그 애니메이션을 건너뛰게 표시를 둔다.
