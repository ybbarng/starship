# 선실과 지도 (`starship-map/1`) — 설계

2026-10-29, 비서 세션이 씀. 상태: **제안(1단계 착수)**.

## 왜

몇 주에서 몇 달 가는 큰 프로젝트는 다음을 한눈에 알기 어렵다.

- 전체가 얼마나 크고, 지금 어디까지 했나
- 지금 어디를 공사하고 있나
- 내가 골라야 할 것과 누구와 이야기해야 하는지

지금은 이런 것들이 handoff 문서의 긴 글, Linear 카드, 초안 파일에 흩어져 있다. 게다가 일을 하다 보면 처음 생각한 것보다 항목이 늘어나는데, 그 늘어난 모습도 보이지 않는다.

닌텐도가 젤다 맵 곳곳에 "공사중" 표지를 붙여 두고 사람들이 맵을 돌아다니며 만들었다는 이야기처럼, **프로젝트 하나를 지도 한 장으로** 보이게 한다.

## 개념

| 이름 | 뜻 | 화면 |
|---|---|---|
| **선실** | 승무원(프로젝트) 하나의 방. 지금 갑판 화면에서 승무원을 누르면 들어간다 | `/crew/[id]` |
| **지도** | 그 프로젝트의 전체 그림 한 장. 저장소 안의 `map.json` | 선실 가운데 |
| **구역** | 일의 한 부분. 구역 안에 구역을 둘 수 있다(최대 3단) | 지도 위 땅 한 칸 |
| **구역 상태** | `fog` 안개(아직 손대지 않음, 윤곽만 앎) · `building` 공사중 · `done` 완공 · `blocked` 막힘 · `dropped` 버림 | 색과 무늬 |
| **지금 여기** | AI 세션(과 내)가 지금 공사하는 구역 | 그 칸 위에 승무원 동물 |
| **갈림길** | 정해야 할 것. 누가 정하는지(`owner`)와 선택지, 추천안을 함께 적는다 | 구역 위 표지판 ⑂ |
| **교신** | 다른 사람과 이야기해야 하는 것. 초안 → 보냄 → 답 기다림 → 끝 | 구역 위 안테나 📡 |
| **발견** | 처음 계획에 없다가 하는 중에 생긴 구역. 언제 생겼는지 적는다 | 새로 생긴 땅 표시, 위쪽 "처음 12 → 지금 19" |

## 데이터: `map.json`

### 어디에 두나

`map.json`은 프로젝트 저장소 안에 두고 일과 같은 커밋으로 고친다. 비서는 아래 순서로 찾아 처음 나오는 것을 쓴다.

1. `<세션 폴더>/map.json`
2. `<세션 폴더>/docs/map.json`
3. `<세션 폴더>/*/docs/map.json` (예: 세션 폴더가 git이 아니고 그 아래 저장소가 있을 때)

### 모양

```jsonc
{
  "map": "starship-map/1",
  "title": "온라인 상점",
  "goal": "첫 고객이 주문하고 결제·배송까지 끝난다",   // 끝났다고 볼 기준
  "baselineAt": "2026-10-22",          // 처음 계획을 세운 날. 이날 이후 생긴 구역이 '발견'
  "updatedAt": "2026-10-29T10:12:00+09:00",
  "here": "server-payment",           // 지금 공사하는 구역 id. 없으면 생략
  "regions": [
    {
      "id": "server-payment",
      "title": "서버: 결제",
      "parent": "server",              // 없으면 맨 위 구역
      "status": "building",
      "size": 3,                        // 1~5, 대략의 크기. 지도에서 차지하는 넓이. 기본 1
      "summary": "결제 대행사 A로 확정(결정 0002). 승인 API 구현 중",
      "next": "환불 정책을 Kim에게 확인",
      "since": "2026-10-23",            // 이 상태가 된 날
      "found": "2026-10-23",            // 발견된 구역만. 처음 계획에 있던 것은 생략
      "links": [
        { "label": "결정 0002", "path": "docs/decisions/0002-payment.md" },
        { "label": "PAY-12", "url": "https://example.com/PAY-12" }
      ],
      "signs": [
        {
          "id": "receipt",
          "type": "fork",              // 갈림길
          "title": "영수증 발급 방식",
          "owner": "me",               // me = Brice, 그 밖에는 사람 이름
          "options": ["A 대행사 영수증", "B 직접 발급"],
          "recommend": "A 대행사 영수증",
          "status": "open",            // open · decided
          "decided": "A 대행사 영수증"      // decided일 때
        },
        {
          "id": "kim-refund",
          "type": "talk",              // 교신
          "title": "환불 정책",
          "with": "Kim",
          "status": "draft",           // draft · sent · waiting · done
          "path": "docs/drafts/kim-questions.md"
        },
        {
          "id": "outage",
          "type": "risk",              // 위험
          "title": "대행사 장애가 길 때 동작 미정"
        }
      ]
    }
  ]
}
```

- 회사 프로젝트의 `map.json`에는 회사 내용이 들어간다. 그래서 그 저장소 안에만 두고, 비서 저장소에는 옮기지 않는다. 비서는 읽어서 화면에 넘기기만 한다.
- 진행률은 `size` 합으로 센다. `done` 크기 ÷ (`dropped`를 뺀 전체 크기)이고, 자식이 있는 구역은 자식으로만 센다.

## 꼭 지킬 규칙과 보장 방법 (질문 ②)

| 규칙 | 보장 |
|---|---|
| 형식이 맞다 | zod 스키마의 원본은 starship `src/protocol/map.ts`이고, 비서도 같은 모양으로 읽을 때 검사한다. 틀리면 그 승무원에게 "지도 파일이 틀렸다" 경보를 띄우고, 화면에는 마지막으로 맞았던 지도를 보인다 |
| `id`가 겹치지 않고, `parent`가 있고, 고리가 없다 | 같은 검사기 |
| 지도가 실제와 어긋나지 않는다 | ① 각 프로젝트 `CLAUDE.md`에 "구역을 시작하거나 끝내거나, 새 일·갈림길·교신이 생기면 **같은 커밋에서** `map.json`을 고친다"는 규칙을 둔다. ② 비서가 저장소의 마지막 커밋이 `map.json`의 마지막 변경보다 2일 넘게 앞서면 "지도가 오래됨"(warn)으로 표시한다 |
| 항목이 늘어도 지도가 깨지지 않는다 | 좌표를 손으로 적지 않는다. 화면이 `size`와 계층으로 자동 배치한다(아래) |

## 사람과 AI가 어떻게 찾아 쓰나 (질문 ③)

- **사람**: starship 갑판에서 승무원을 누르면 선실로 들어간다. 갑판의 승무원 옆에는 진행률과 내가 정할 갈림길 수만 작게 보인다.
- **AI 세션**: 세션을 시작할 때 handoff와 함께 `map.json`을 읽는다. 지도는 상태와 다음 일을 정리한 **목차**이고, 자세한 내용은 `links`로 문서를 가리킨다. handoff는 마지막 세션의 이야기만 담고, 구역 상태를 다시 적지 않는다(둘이 어긋나지 않게).
- **비서**: 매일 아침 `owner: me`인 열린 갈림길과 `draft`·`waiting` 교신을 모아 보고한다(3단계).

## 화면: 선실

```
┌ 온라인 상점 ─────────────── 진행 41% ▓▓▓▓░░░░░ · 처음 12 → 지금 19 (+7 발견) · 지도 갱신 2시간 전 ┐
│ ┌──────────── 서버 ─────────────┐┌──── 프론트 ────┐┌─ 운영 ─┐  │ 선택한 구역 ────────────── │
│ │ 결제   🦊 🚧  ⑂ 📡 │ 상한 ░░ ││ 진입 ✅ │ 화면 🚧 ││ ░░░░░ │  │ 서버: 결제 · 공사중   │
│ │──────────────────────│───────││─────────────────││ ░안개░ │  │ 다음: 환불 정책 확인     │
│ │ 주문서 ✅          │ 환불 ⛔ ││ 장바구니 ⑂      ││ ░░░░░ │  │ ⑂ 영수증 발급 방식 (내가)   │
│ └──────────────────────┴───────┘└─────────────────┘└────────┘  │ 📡 Kim — 초안              │
│ 내가 정할 것 ⑂ 3 · 교신 📡 2 · 막힘 ⛔ 1                        │ 링크: 결정 0002, PAY-12    │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **배치**: squarified treemap. 맨 위 구역이 대륙, 그 안의 구역이 땅이 된다. 넓이는 `size`다. 구역이 늘면 땅이 나뉘기만 하니 손으로 다시 그릴 필요가 없다.
- **상태 표현**:
  - `fog`: 안개 무늬로 윤곽만 보인다.
  - `building`: 노란 공사 줄무늬와 🚧.
  - `done`: 차분한 색과 깃발.
  - `blocked`: 붉은 테두리.
  - `dropped`: 흐리게 하고, 기본은 숨긴다.
- **표지**: 갈림길·교신·위험은 구역 위 아이콘으로 놓는다. 내가 정할 갈림길만 눈에 띄게 한다.
- **지금 여기**: `here` 구역 위에 그 프로젝트의 동물 선원이 앉아 있다. 세션이 일하는 중이면 움직인다.
- **발견**: `found`가 최근 7일 안이면 "새 땅" 표시를 한다. 위쪽에 처음 대비 늘어난 수를 적는다.
- **오른쪽 판**: 구역을 누르면 요약, 다음 일, 표지 목록, 링크가 나온다. 링크의 `path`는 저장소 파일이라 화면에서 열지 않고 경로만 보인다.

## 프로토콜에 더하는 것 (starship/1 안에서, 더하기만)

- `GET {base}/v1/crew/{id}/map` → `{ map: Map | null, problems?: string[], stale?: boolean, mapAt?: number }`
  - `map: null`은 지도가 아직 없다는 뜻이다. 선실에는 "지도가 아직 없어요"를 보인다.
  - `problems`는 형식 검사에 걸린 것이다. 화면은 마지막으로 맞았던 지도를 그대로 보인다.
- `Crew`에 선택 필드 `map?: { progress: number; regions: number; found: number; forksForMe: number; stale: boolean }`를 더한다.

## 요구사항이 바뀌면 (질문 ④)

- 필드 더하기(예: 담당자, 마감, 위치 좌표)는 `starship-map/1` 안에서 한다. 화면은 모르는 필드를 무시한다.
- Linear 카드와 이어 붙이기는 `links`에 카드가 이미 있으니, 나중에 어댑터가 카드 상태를 읽어 구역 상태와 다르면 알리는 정도로 더할 수 있다. 형식은 바뀌지 않는다.
- 손으로 배치한 "진짜 지도" 그림을 원하게 되면 구역에 `pos`를 선택 필드로 더하고, 없는 구역만 treemap으로 놓는다.
- 갈림길에 선실에서 바로 답하기는 `POST /v1/actions`에 `{ target: "sign", crewId, id, action: "answer", answer }`를 더한다. 비서가 받아 그 세션에 넘기고, 세션이 `map.json`을 고친다. 화면이 파일을 직접 쓰지는 않는다. 쓰는 곳을 하나로 두려는 것이다.

## 다른 방법과 고른 이유 (질문 ⑤)

| 방법 | 버린 이유 |
|---|---|
| Linear 프로젝트·마일스톤을 그대로 지도로 | 개인 프로젝트에는 없다. 갈림길·교신·발견을 담지 못한다. 카드는 일을 쪼갠 단위이지 전체 그림이 아니다 |
| handoff·PLAN 같은 마크다운 체크리스트를 읽어서 | 쓰기는 쉽지만 상태·표지를 글에서 뽑는 일이 깨지기 쉽다. 지금 handoff가 길어져 안 보이는 것이 바로 이 문제다 |
| 지도를 비서 `local/`에 모아 두기 | 각 세션이 자기 저장소 밖을 써야 해서 권한 확인이 늘어난다. 일과 같은 커밋으로 묶이지 않아 어긋나기 쉽다 |
| 좌표를 손으로 놓는 그림 지도 | 보기는 가장 좋지만 구역이 늘 때마다 AI가 배치를 다시 해야 한다. 늘어나는 프로젝트에 약하다. 나중에 `pos`로 더할 수 있게 열어 둔다 |
| **저장소 안 `map.json` + 자동 배치(고름)** | 일과 같은 커밋으로 고쳐지고, 늘어나도 깨지지 않고, 형식을 검사할 수 있다 |

## 단계

1. **형식과 선실 화면**
   - starship: `src/protocol/map.ts` 스키마, `/crew/[id]` 선실(treemap·오른쪽 판·위쪽 줄), 데모 지도 한 장, 갑판에서 선실로 들어가는 길.
   - 비서: 지도 찾기·검사·`/starship/v1/crew/{id}/map`, `Crew.map` 요약.
2. **첫 지도 세 장**: 큰 프로젝트 세 곳의 세션이 지금 문서를 보고 `map.json`을 처음 그리고, 각자 `CLAUDE.md`에 갱신 규칙을 더한다.
3. **살아 있게**: "지도가 오래됨" 표시, 아침 보고에 갈림길·교신 넣기, 선실에서 갈림길에 답하기, `map.json`의 git 기록으로 "늘어난 모습" 그래프 그리기.
